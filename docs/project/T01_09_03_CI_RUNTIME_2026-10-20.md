# T01.09.03 – CI-Laufzeit vor/nach der Wheelcache-Optimierung (Messung 2026-10-20)

Kriterium: „Gesamtlaufzeit bei identischer Testabdeckung vor/nach Optimierung messen“.
Optimierung: `73fd965e` (T01.09.01/02) – der native Wheelcache-Schlüssel kommt aus Compiler/ABI/SDK/Flags
(`steps.native_cache.outputs.key`) statt aus `hashFiles(…, '.github/workflows/desktop-platforms.yml')`.

## Methode

- Quelle: öffentliche GitHub-Actions-API (Jobs/Steps je Lauf), Workflow „Desktop Platforms“, nur erfolgreiche Läufe.
  Rohdaten: `T01_09_03_CI_TIMINGS_2026-10-20.json` (Lauf-ID, Head-SHA, Minuten je Job und Schritt).
- Gemessen wird die **Job-Laufzeit** (started→completed), nicht die Lauf-Wanduhr: Die Wanduhr enthält die
  Runner-Warteschlange (15–112 min im Zeitraum) und ist für den Vergleich unbrauchbar.
- „Identische Testabdeckung“: Die Testschritte (Smoke, Regression) haben sich zwischen den Läufen geändert, ein
  Vergleich der ganzen Jobs ist daher **nicht** abdeckungsgleich. Abdeckungsgleich ist der Schritt
  „Install native dependencies (compile …)“: Er führt keine Tests aus, nur den nativen Wheel-Build bzw. den
  Cache-Restore, und genau dort wirkt die Optimierung.
- Stichprobe: 5 Läufe vor (`89f0c92c`, `38fac62f`, `0343232d`, `e11fe62c`, `105bf449`), 6 nach
  (`53cfadbe`, `adc297cf`, `f4451b2d`, `c260274e`, `7e083f5f`, `24bd29e0`), je Linux, macOS ARM, macOS Intel.

Die Mediane sind praktisch gleich: Bei Cache-Treffer ändert die Optimierung nichts an der Laufzeit.

Die Wirkung zeigt sich bei **Änderungen an der Workflow-Datei**:

- Vor: `105bf449` folgt auf Workflow-Änderungen (`b6f947ff`, `318d4a73`, `0468da66`) → Cache verfehlt,
  Install native 3,1 (ARM) / 3,6 (Linux) / 9,8 (Intel) min; Jobs 14,7 / 12,6 / 28,8 min.
  `e11fe62c`: Intel 6,4 min (Teil-Neubau).
- Nach: `desktop-platforms.yml` wurde nach `73fd965e` 14-mal geändert, u. a. in `adc297cf` selbst.
  Dort Install native 0,6 / 0,7 / 1,7 min → Cache getroffen. In keinem der 6 Läufe danach ein Neubau (max. 2,0 min).

Ersparnis im Install-Schritt je Workflow-Änderung (Neubau `105bf449` minus Median nach): ARM ≈ 2,6 min,
Linux ≈ 3,0 min, Intel ≈ 8,1 min, zusammen ≈ 13,7 Runner-Minuten pro betroffenem Lauf.

## Grenzen (UNSICHER)

- Kleine Stichprobe (5/6), Runner-Leistung schwankt (Smoke Intel 7,7–13,3 min). Kein Signifikanztest.
- Kein abdeckungsgleicher Vergleich der ganzen Jobs (Testschritte geändert); nur der Install-Schritt ist vergleichbar.
- Windows (Build Windows EXE / Windows Smoke) nicht gemessen; der Cache-Schlüssel dort ist hier nicht geprüft.
